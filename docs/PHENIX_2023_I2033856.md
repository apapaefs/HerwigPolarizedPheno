# PHENIX 2023: three-component polarized prompt photons

Use `scripts/run_PHENIX_2023_I2033856_WithLoop.py` for the combined campaign.
It generates independent `PP`, `PM`, `MP`, and `MM` samples of:

| Channel key | Hard process |
| --- | --- |
| `photon` | `MEGammaJet`: tree-level photon + jet |
| `fragmentation` | `MEQCD2to2`: QCD dijets, with photons from the QED shower |
| `gammajet_loop` | `MEPP2GammaJetLoop`: massive-quark-box `gg -> gamma g` |

Each sample has QCD+QED showers, spin correlations, hadronization and nominal
MPI enabled. The beams are polarized protons at 510 GeV; the PDFs are
NNPDF40 NLO and NNPDFpol2.0 NLO, member 0 by default. Separate samples are
normalized to their own calculated cross sections. Shards are averaged within
a hard-pT slice, disjoint slices are added, and the three channels are added
**per helicity before** forming `A_LL = (PP + MM - PM - MP)/(PP + MM + PM + MP)`.
Independent statistical variances are propagated at each step. The loop rate
is calculated by Herwig; no externally estimated percentage is imposed.

This is a tree-level-plus-shower prediction with a leading loop-induced
contribution (`alpha_EM * alpha_s^3`), not a complete NLO or NNLO calculation.
The tree photon/dijet combination retains the existing unmerged prescription;
this workflow does not introduce matrix-element/shower overlap subtraction.
The loop addition and the sampling improvements do not change that accuracy
statement. `LO+PS (polarized; full spin)` is the compact plot legend; the full
physics definition and generated components are recorded in the provenance.

## Generator prerequisites

Activate a compatible polarized Herwig/Rivet/YODA/LHAPDF installation as in
[runtime-compatibility.md](runtime-compatibility.md). Herwig source belongs to
the separate [herwigdispol repository](https://github.com/apapaefs/herwigdispol).
The installed libraries, not just a source checkout, need:

- `MEPP2GammaJetLoop` with `AmplitudeMode Massive` and its spin-density interface;
- the physical two-helicity photon/gluon spin handling in `MEPP2GammaJet`;
- the outgoing-gluon QED partner fallback for the otherwise partnerless hard
  photon in `gg -> gamma g`;
- the polarized ISR PDF-coordinate correction (`xfx` for momentum fractions),
  merged in herwigdispol commit `b9475a3de6f41c16d2d0ae78adceee6c6d9caa72`;
- weighted `QtoQGammaSudakov:EnhancementFactor` support and detuning 2.

The photon helicity and partner-finder changes have existed as local generator
patches; do not assume that pulling this phenomenology repository installs
them. Confirm those changes in your generator installation and run its native
checks before production. Source-level loop-amplitude checks and the old/new
partner replay test serve different purposes. Neither replaces a smoke run
with the actual installed executable. Campaign manifests fingerprint the
runtime libraries, PDFs, generated cards and Rivet plugin. This repository
does not ship or rebuild those libraries. Results generated before the ISR
correction are not made corrected results by replotting or pooling them.

## Default sampling

Only the **WithLoop** descriptor opts into these defaults. The other PHENIX
variants retain their explicit-options behavior.

`--photon-enhancement 12` is the default for the **fragmentation channel only**.
The generated card sets `QtoQGammaSudakov:EnhancementFactor 12` and
`SplittingGenerator:Detuning 2` before `saverun`. Herwig supplies the compensating
event weights, including its shower probability correction. Do not divide
histograms by 12 or apply a second correction. This improves sampling of rare
quark-to-photon radiation; it is not a physical enhancement of the photon rate,
and accepted counts need not rise twelvefold. Use `--photon-enhancement 1` for
the detuning-matched control. Tree photon and loop samples are not enhanced.

The five **Born hard-process pT** intervals are 4--8, 8--12, 12--16, 16--20,
and 20--infinity GeV. These are generation strata, not final-photon analysis
bins. The open upper tail is included because migration can feed measured bins.
The default central campaign has **125 million generated events total**:

| Born pT (GeV) | Tree photon / helicity | QCD dijet / helicity | Loop / helicity |
| --- | ---: | ---: | ---: |
| 4--8 | 650,000 | 15,000,000 | 40,000 |
| 8--12 | 425,000 | 5,400,000 | 20,000 |
| 12--16 | 325,000 | 3,400,000 | 20,000 |
| 16--20 | 175,000 | 2,250,000 | 10,000 |
| 20--infinity | 175,000 | 3,350,000 | 10,000 |
| Sum per helicity | 1,750,000 | 29,400,000 | 100,000 |

Multiply the last row by four helicities: 7M tree + 117.6M dijet + 0.4M loop.
This starting allocation scales down the previous 1.25B-event production plan
by ten. It is a practical preset, not a claim of optimal allocation or a
guarantee of final precision. Low-pT QCD events rarely yield an accepted isolated
photon, so that channel needs much larger sampling pools, especially in the
lowest stratum. Judge improvements using weighted bin uncertainties and
effective sample size, not accepted counts alone.

`--jobs` sets concurrency. `--shards` divides each table entry; it does not
multiply its event count. At central scale there are 60 logical samples
(3 channels x 4 helicities x 5 slices); `--shards 72` makes 4,320 shard jobs.
Extra scale/PDF points multiply the nominal event budget.

## Commands

Run from this checkout in the activated environment. Preview first:

```bash
python3 scripts/run_PHENIX_2023_I2033856_WithLoop.py \
  --output-root "$HOME/HerwigPol/work" \
  full --tag phenix-full --jobs 72 --shards 72 \
  --seed-base 526000000 --dry-run
```

Remove `--dry-run` to generate, postprocess and plot. For an installation smoke
test use a separate tag and `--smoke --shards 1 --jobs 4`: 100 events per logical
sample, 6,000 total, with EF12 and all five slices. This tests execution, not
statistical precision. No job is submitted merely by cloning this repository.

To change sampling, add options to `prepare`, `campaign` or `full`:

- `--lo-events 600000`: equal counts for every channel/helicity/slice, replacing
  the default table; 36M total at central scale.
- `--hard-pt-events fragmentation=15000000,5400000,3400000,2250000,3350000`:
  explicit counts for that channel. Repeat for `photon` and `gammajet_loop`.
  Once any explicit budget is supplied, unlisted channels use `--lo-events`
  (200,000 if omitted), not the table above.
- `--hard-pt-edges 4,inf`: one inclusive generation interval; custom edges also
  disable the default allocation. Supply matching budgets or `--lo-events`.
- `--photon-enhancement 1`: control without enhanced photon proposals.
- `--scales all`: generate 0.5, 1 and 2 times the nominal hard scale.

For the full 1.25B allocation, specify all three channel lists from the table
multiplied by ten. The resolved plan and `manifest.json` record the actual
budgets, enhancement, seeds and slices. Use distinct seed ranges for independent
campaigns. Re-run an interrupted command with identical settings; add
`--recover-failed` for failed shards. Changes to generation settings require a
new tag, and changing defaults does not bypass an old manifest's checks.

Plotting alone uses saved results and does not apply new sampling defaults:

```bash
python3 scripts/run_PHENIX_2023_I2033856_WithLoop.py \
  --output-root "$HOME/HerwigPol/work" plot --tag phenix-full
```

Outputs live below `WORK/PHENIX_2023_I2033856_WithLoop/TAG/`. Keep the manifest,
resolved descriptor, shard YODAs and provenance. `postprocess/prediction.yoda`
contains the combined prediction; `postprocess/summary.json` retains the physics
and sampling settings. The default three data comparisons use normalized
residuals `(MC-Data)/sigma_Data` underneath, with MC uncertainty visible.
Use `--include-diagnostics` for separate channel and spin-closure plots.

## Analysis, references and checks

The common analysis is `analyses/rivet/pp/PHENIX_2023_I2033856.cc`. It counts
every non-hadron-decay photon in `|eta|<0.25`, with the published spectral and
asymmetry bins. Isolation uses a cone of radius 0.5, other-particle energy
less than 10% of photon energy, charged-particle momentum at least 0.2 GeV
and neutral-particle energy at least 0.3 GeV. Same-event photons in one bin
contribute together to its statistical variance. Inter-bin covariance is not
provided. No detector simulation or decay-background subtraction is repeated.

The unchanged pinned reference snapshots under
`data/phenomenology/PHENIX_2023_I2033856/` reproduce Tables 1 and 2 of
[HEPData ins2033856](https://www.hepdata.net/record/ins2033856), associated with
[the PHENIX publication](https://arxiv.org/abs/2202.08158).
Global luminosity, relative-luminosity and beam-polarization uncertainties stay
separate; the residual panel is not a full covariance goodness-of-fit test.

```bash
python3 -m unittest discover -s scripts/tests -p 'test_phenix*.py'
python3 scripts/check_phenix2023_rivet.py --output /path/to/new/phenix-check
```

The native check builds the plugin and controlled HepMC fixtures to test
ancestry, cuts, isolation, photon multiplicity, normalization and variances.
It does not generate a production campaign or validate the Herwig amplitudes.

Other entry points are retained: the base wrapper is tree+dijet;
`run_PHENIX_2023_I2033856_MEGammaJetLoop_Only.py` generates only the loop;
`run_PHENIX_2023_I2033856_MEGammaJet_Only.py` reproduces the historical tree-only
analysis, including its older charged-pT threshold and per-photon errors.
That historical variant differs in analysis as well as channel content.
For existing compatible two-component campaigns plus a loop-only addition,
see [the pooling instructions](phenix-loop-combination.txt). A single WithLoop
campaign needs no separate pooling step.
